# CRF-Inertial RNN + External Kalman v20

This is the recommended consolidated design after the failed v10-v19 closed-loop experiments.

## Core design

Only the current UAV frame, current SAT candidate images/features, and the previous recurrent state are used by the learned temporal system.

Pipeline:

1. Previous RNN state contains velocity and acceleration.
2. A second-order inertial polynomial predicts the next position:
   `next_search = previous_final + velocity + 0.5 * acceleration`.
3. The full 6x6 SAT candidate grid is extracted around that forward prediction.
4. A CRF-inspired candidate layer refines all 36 candidate scores BEFORE HardMS.
5. The candidate layer combines:
   - UAV/SAT embeddings,
   - standardized raw retrieval logits,
   - raw candidate probabilities,
   - relative candidate xy/radius,
   - polynomial transition residual,
   - a weak soft forward-direction term,
   - previous recurrent state.
6. HardMS runs on the refined candidate logits.
7. A plain RNNCell receives the refined visual context, HardMS diagnostics, and previous state.
8. RNN outputs:
   - visual residual correction,
   - measurement uncertainty,
   - velocity,
   - acceleration,
   - next recurrent state.
9. The visual measurement is passed to an external [x,y,vx,vy] Kalman filter.
10. Kalman output is the final localization.

## Why there is no hard forward 3x6 crop

Forward search is already implemented by moving the center of the full 6x6 grid to the polynomial prediction. A hard 3x6 mask would remove recovery candidates when the motion prediction overshoots or the UAV turns. The forward preference is therefore a soft candidate-score prior instead of a hard removal rule.

## What was reused from the old RTL-CRF

The old CRF used:
- standardized retrieval score,
- raw probability,
- relative candidate xy,
- radius,
- learned emission,
- speed / acceleration / direction consistency.

v20 keeps that logic but makes it compatible with a one-frame recurrent interface:
- the CRF emission is evaluated on the current 36 candidates;
- the previous RNN state provides the second-order transition information;
- the full 5-frame lattice is replaced by a persistent recurrent state.

## Training

### Stage 1: local candidate + next-step warmup

Route A only.

The current GT position plus random jitter is used only to construct a valid local 6x6 crop. GT is never fed to the network.

The model learns:
- soft 36-candidate target distribution,
- refined HardMS measurement,
- next displacement,
- velocity,
- acceleration,
- measurement uncertainty.

### Stage 2: adaptive autoregressive rollout

No per-frame teacher center.

Each training chunk is initialized once, then every later search center is generated by the previous model state.

The horizon begins at 4 and advances only when:
- training candidate capture >= 90%,
- training predicted-center error <= 7 m,
- Route-A validation-episode capture >= 70%,
for two consecutive epochs.

Possible horizons:
4 -> 8 -> 16 -> 32 -> 64 -> 128 -> full train split.

## Validation and Early Stop

Checkpoint selection uses several 64-frame closed-loop Route-A validation episodes initialized only at each episode's first GT position.

The W0-to-end full Route-A rollout is still logged as a stress test, but it is not used as the only checkpoint score because a catastrophic early drift makes every model look like ~300 m error.

Early stopping:
- starts after stage-2 epoch 12,
- patience = 8,
- meaningful episode-val improvement = 0.15 m.

## Test

Route B and Route C:
- initialize at known W0 only,
- no GT reset,
- no GT model input,
- no waypoint frame-index switching,
- full closed-loop inference,
- final localization is the Kalman output.
